## 当前功能与实现

UI2-08 接入当前记录读取、原版本、本人更正权限、逐项内容、独立时间、原因及草稿。没有修改的医学时间保持准确原引用，更正输入不根据记录类型重写 sample_time_origin。前端采用明确字段序列化和当前对象校验；保存后必须核验实际回执及重新读取的版本。当前验证使用已有记录和更正字段的只读技术投影，完整真实更正及依赖失效保持 NOT_RUN。

保存后的 raw_numeric 使用 decimal.js 10.6.0 的 Decimal 比较数值，raw_text、原始单位及其他内容分别准确核验；序列化继续保留用户原文。依据为 [decimal.js 官方 API](https://mikemcl.github.io/decimal.js/)。

更正草稿允许保留尚未完成的数值输入与时间选择。正式提交前校验完整输入，尚未发送的校验失败保留编辑能力；接口发送后结果未知时要求核验原记录。草稿结构校验继续核验字段身份、出处与原版本，实际保存与恢复组合保持 NOT_RUN。

输入、逐项字段、回执和草稿使用明确 Schema。服务端直接使用已登记及锁定的 jsonschema 4.26.0 校验输入，核验完整字段顺序、原 value_type 与 concept_code；前端保存后核验原因、逐项内容、原件和来源引用。草稿恢复要求当前患儿、记录、原版本及字段身份一致；原版本变化时停止提交。进入后台取消当前请求，结果未知时禁止重复提交；需要重新查询当前记录。
