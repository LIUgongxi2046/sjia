## 检索与输入依据

读取依据：[后端 LLD 第 4.2、6.1 节](../../sJIA合并MAS预警平台后端LLD.md)、[handshake 第 2 节](../../backend-design/handshake.md)、[protocol.schema.json FieldConfig* 定义](../../backend-design/protocol.schema.json)、T02 模型。

关键采用结论：

- 配置内容不可变，修改产生新版本；`config_version` 以 `(config_key, version)` 唯一，checksum 为按键排序的 UTF-8 JSON 摘要。
- 每个 kind 使用登记的成熟 Schema 校验；未经登记的 kind/schema 拒绝（`CONFIG_KIND_UNREGISTERED` / `CONFIG_SCHEMA_UNAVAILABLE`）。
- 保存、批准、验证、启用是独立操作；启用要求批准与验证证据齐备，并提升 environment_gate.version 与 publication_epoch。
- `field_config_read` 来源为 `config_version(kind=content, schema_version=field-config-1)`；无获准配置返回 disabled，指定非当前版本返回 read_only。

## 决策与约束

- 配置不可变：`register_config` 每次创建新版本，使用 PostgreSQL 事务锁分配同 config_key 的递增版本；具体内容还须通过 schemas.VALIDATORS，缺少正式结构时拒绝。
- 批准与验证分离：批准记录准确环境、正文摘要、人员、角色、用途和有效期；验证读取批准来源的真实报告，核查实际运行、数据、制品和执行人员；启用重新检查全部证明。
- 未知单位映射不换算，保存不自动启用；单位转换只使用获准 mapping 的 multiplier/additive。
- 字段配置校验：field_code 唯一、categorical 必须 allowed_values、decimal 上下限有序、watch_field_codes 属于当前字段集合。
