## 检索与输入依据

读取依据：[后端 LLD 第 5 节](../../sJIA合并MAS预警平台后端LLD.md)、[handshake 第 6 节](../../backend-design/handshake.md)、T02 模型、[runtime.schema.json](../../backend-design/runtime.schema.json)。

关键采用结论：

- 任务状态机 `accepted→blocked/queued/running→…→终态`，状态转换通过条件 UPDATE 要求 status、status_version、lease_generation 一致；终态不改写。
- Dispatcher 用 `FOR UPDATE SKIP LOCKED` 领取 Outbox 租约，事务外 publish，消息只含 event_id/task_id/schema_version；Redis 仅传消息，业务结果读 PostgreSQL。
- 旧租约提交影响行数必须为零；消费去重由 consumer_receipt 唯一约束保证。

## 决策与约束

- `task_type` 补齐 `file_validation`（原 7 类），并重建 DB 值域 CHECK 为 8 类，匹配 backend-design/schema.sql 的 ALTER。
- `enqueue` 只作用于 accepted，不覆盖 running 或终态；`acquire_lease` 只在 accepted/queued 且租约空闲时生效。
- Celery result backend 不承载病例结果；消息不含病例正文。
