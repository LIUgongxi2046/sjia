## 检索与输入依据

读取依据：[后端 LLD 第 2 节](../../sJIA合并MAS预警平台后端LLD.md)、[数据 LLD TX01—TX08](../../sJIA合并MAS预警平台数据LLD.md)、[protocol.schema.json](../../backend-design/protocol.schema.json)、T02 模型。

关键采用结论：

- 判定式 `allow(subject, action, object, purpose, environment, now)` 来自后端 LLD 2.1：Session 有效、principal active、auth_epoch 一致、environment_gate.enabled、授权有效、患儿与范围匹配、字段子集、用途与环境获准、家庭请求要求有效关联。
- 动作分两类：病例动作用 `access_grant`，服务动作用 `service_role_grant`；`is_staff/is_superuser/Django Group` 均不自动授予病例读取。
- 家庭输入不能提供 patient_id、author_id、verifier_id、verification_status、quality_status、rule_result、approved_by、permissions；额外字段直接拒绝。

Policy Gate 判定顺序：principal active → auth_epoch 匹配 → environment enabled → 服务动作查 service_role_grant / 病例动作查 access_grant（有效性、范围、字段子集、关联）。

## 决策与约束

- 授权结果只有 Allow / Deny；Ask 由本人确认或受控批准流程完成，不产生额外的家庭确认页面。
- 审计写入失败时异常向上传播，调用方据此拒绝受保护操作（fail-closed）。
- 写入固定锁顺序与 `lock_timeout < statement_timeout < request_deadline` 在 T05/T06 业务事务中落实；本任务提供读取隔离级别与判定服务。
- 家庭投影过滤未批准字段，不返回 null 占位。
