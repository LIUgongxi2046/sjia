# T41 多事实提取与逐项医学时间确认

日期：2026-10-09。开发状态 IMPLEMENTED；完整真实验收 V41 NOT_RUN。需求 FR-13、FD-61／62、GRAC-01、AC-AI-01。任务状态以 [交付记录](../../planning/delivery-ledger.json) 为准。

## 功能与来源

实际模型提取整页文字、文书类别候选、每项原值、单位、比较符、原始时间文字、历史病史、此次病情、出院结论、计划治疗、实际治疗、否定和无法读取区域。完整原始回执、请求标识、usage、费用依据和候选分别持久保存。每项 source_quote 必须属于整页原文；结构不合格拒绝采用。医学日期与专业资格需要独立确认，平台取得时间使用实际保存时刻。

本人逐项选择按原文确认、修订后确认、未知或排除。正式采用要求全部候选决定完整、准确来源和当前权限；修订或排除填写依据。零项候选需要明确确认，保留原件及完整提取回执。未知原值保留 unknown，数字使用十进制字符串，数值末尾零持续保留。没有批准字典和单位映射的内容保存原文，不自动产生临床概念或规范化数值。

医学时间、文书形成时间、原始时间文字和平台取得时间分别保存。本人逐项确认时间，月份保留年月，未知时间保持未知。医学时间与语境输入一致；共同时间需要明确原文依据。已有就诊选择核查患儿、来源字段、准确记录版本及当前权限。确认、更正、记录、事实、出处、依赖、资料版本和审计使用实际事务。

更正创建新的 RecordVersion、RecordField、ArchiveFactVersion，保留历史原值、出处和初始确认；新字段保持 unverified。事实依赖指向准确记录、原件、页面、医学时间、文书与确认依据，旧依据失效后停止下游采用。记录和历史接口按准确字段返回事实引用。

持久 WriteIntent 保存原请求正文、校验值、准确操作和目标、身份、权限与世代。重复提交返回原回执；过期原请求核查当前条件后重新准备。未知保存结果禁止自动新建请求。恢复期间表单冻结，刷新查询本人原请求。撤权后停止读取候选、原件和私人请求正文。原件读取核查页面、上传组、文件版本、checksum、当前原件权限，支持准确 Range 字节。

## 页面及接口

UI2-27 保留原稿标题、流程、逐项编辑、比较符、时间精度、语境、就诊、原文、逐项确认、保存及归组入口。更正弹层使用同一正式编辑器，键盘焦点保持弹层范围。UI2-33 保留七项元数据和主动查看原件入口，读取准确原页及候选元数据。切换患儿、原页或批次建立对应状态；后台清理私人内容，恢复时重新核查身份与权限。私人正文不进入 localStorage、sessionStorage 或导航参数。

| 接口 | 返回或行为 |
| --- | --- |
| GET /api/v2/archive-pages/{page_id}/candidates | 完整提取、逐项候选、出处和已经保存的本人决定 |
| GET /api/v2/archive-pages/{page_id}/facts | 当前准确事实及允许动作 |
| GET /api/v2/archive-pages/{page_id}/original | 原件版本、授权、副本和元数据 |
| GET /api/v2/archive-pages/{page_id}/original/content | 当前原页权限控制的准确原件字节 |
| POST /api/v2/archive-pages/{page_id}/confirm | 正式确认、事务保存、原回执 |
| GET /api/v2/archive-facts/{fact_id} | 准确当前事实、语境与出处 |
| GET /api/v2/archive-facts/{fact_id}/versions | 当前权限下的准确历史与签名分页 |
| POST /api/v2/archive-facts/{fact_id}/corrections | 新事实版本、原因与依据失效 |

主要代码为 backend/recognition/archive_extraction.py、archives/fact_candidates.py、fact_writes.py、requests/archive_facts.py、api/views_fact_writes.py、records/service.py、correction.py；前端为 archiveFacts.ts、UI2ConfirmPage.tsx、FactFieldsEditor.tsx、PageOriginalPage.tsx。正式 JSON Schema、AJV 和 TypeScript 使用同一协议。
