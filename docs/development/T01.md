本任务建立后端工程骨架与本地开发环境，使 Django 进程可以启动、连接真实 PostgreSQL，并携带批准的会话/CSRF 配置。

## 决策与约束

- **Python 版本**：HLD 3.1 目标 Python 3.13。本机仅有 3.12.7 与 3.14；Django 5.2 官方支持 3.10—3.13，故本地使用 3.12.7。目标 3.13 因 Homebrew 目录（/usr/local）归属 root 且 sudo 被环境拒绝，无法安装。最终环境验收（V33）须在具备 3.13 的目标环境复验。
- **PostgreSQL 版本**：目标 17；本机仅有 18.4（Homebrew，已链接）。开发集群用 `initdb` 建立在工作区 `.backend-work/pgdata-dev`，端口 5433，用户 sjia（trust 认证，仅本地）。目标 17 同样受 Homebrew 权限阻断。SQL 结构跨 17/18 兼容，迁移与查询验证使用 18.4；V02 的“目标 PostgreSQL 17”仍待目标环境。
- **Redis**：Homebrew 不可安装，改用官方源码 7.2.5 在工作区构建，安装到 `.backend-work/redis`，运行于 127.0.0.1:6379。
- **对象存储**：boto3 已安装；私有对象存储实例（MinIO 或供应商）尚未建立，依据 D01/D09 决定。T12 前建立或记录阻塞。
- **pip SSL**：Python 3.12.7 默认 CA 包缺失，pip 需设置 `SSL_CERT_FILE=$(python3.12 -c 'import certifi; print(certifi.where())')`。该值已记入环境，不关闭 TLS 校验。
- **启用项缺配置立即报错**：`production.py` 启动即调用 `assert_runtime_config`；开发缺省只用于本地。
