## 实现与隔离

[t57_isolated_restore.py](../../tests/operations/t57_isolated_restore.py) 从 `sjia_simulation` 制作数据库转储，在独立 PostgreSQL 实例恢复同名库，复制对象文件与配置证据，再运行恢复探针。启动检查请求隔离 API 的 Bootstrap 接口并要求 HTTP 200。[window4_simulation_settings.py](../../tests/operations/window4_simulation_settings.py) 将数据库、对象目录、配置证据目录和队列名称限制到 `.planning-work/parallel/window4/` 下的独立运行目录。

[t57_relocate_evidence.py](../../tests/operations/t57_relocate_evidence.py) 将恢复库内的配置证据引用指向副本并逐项核对摘要。[t57_isolated_copy_check.py](../../tests/operations/t57_isolated_copy_check.py) 比较来源与恢复副本的文件清单。[t57_recovery.py](../../tests/operations/t57_recovery.py) 执行进程重启、过期租约、取消、重复消费、预算与费用检查。[t57_attempt_terminal_check.py](../../tests/operations/t57_attempt_terminal_check.py) 在隔离库检查取消、迟到用量及待确认状态。[t57_active_purpose_copy.py](../../tests/operations/t57_active_purpose_copy.py) 使用现有有效模拟用途授权调用服务与 Worker 入口，并核验结果和重复消费。

T57 检查没有启动 Redis、共享 Worker 或 Beat，没有消费共享队列，没有发起 Provider 请求或外部发送。隔离 PostgreSQL 在检查后停止。T31 独立模型测量另有一笔已标识模拟 Provider 请求，详见 T31 模型报告。

## 当前预算调用路径

主窗口已将费用函数接入下列调用方，本窗口仅在窗口四隔离数据库复测：

- `archives.page_actions.check_budget` 累计同 Provider 配置键的历史费用并检查币种；当前隔离副本有币种混用记录，接口拒绝继续并返回 `ARCHIVE_BUDGET_CURRENCY_CHANGED`。主窗口需核实该历史配置组合是否为预期模拟数据；保持币种不一致时拒绝预算计算。
- `archives.page_execution.update_batch` 调用 `batch_budget_status`，费用未知时写入并回读 `unknown`。
- `budget_cost` 对已知费用求和，对未调用 Provider 的取消返回 `0`，对 Provider 状态未知且费用缺失返回 HTTP 409 `ARCHIVE_BUDGET_INDETERMINATE`。
