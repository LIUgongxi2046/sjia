## 评价工具与输入规则

工具位于 [window3_evaluation.py](../../tests/clinical/window3_evaluation.py)。`--task T59` 核验冻结状态、准确集合版本、人时分母、标签状态、分组和运行终态。分母按 development 与 validation 分别统计患儿、positive、negative 和 unknown；unknown 单列且不进入阴性分母。验证组为空时，验证指标保持未测量。未来信息检查要求完整事实引用及每项 `known_at` 可得时间；当前 T48 不足结果没有这些逐事实结果，故历史排除检查保持 `NOT_VERIFIED`。

`--predictions <JSON>` 接收 `window3-clinical-predictions-1`，要求准确冻结集合身份、固定规则／程序版本和执行引用、独立提示配对方案、零发布／通知／当前周期修改计数、患儿分组与集合逐项相同、全部冻结观察时段及标签、逐事实来源与可得时间、两种计算的同一输入摘要、事件识别时点、治疗／年龄／感染／资料完整度四类分组及每条提示结局来源，并强制 `data_mode=SIMULATION` 和 `evidence_scope=SIMULATION_FIXTURE_ONLY`。程序核验 `known_at`、跨组患儿和版本差异；逐模式计算敏感度、漏报、PPV、全部观察时间提示数／人时、阴性观察时间提示数／人时、首次提示时间差及 unknown 占比，按登记分组输出，并计算部分识别上下界。场景结果按 development／validation 分开计算；没有 validation 患儿时验证结果明确保持未测量。场景规则版本有 `SIMULATION_ONLY_` 前缀，报告单独放在 `simulation_algorithm_check`；T48 的实际临床指标仍保持 `NOT_MEASURED`。患者相关置信区间仍需获批计算方案。

新增只读捕获入口 [window3_saved_t49_t50_capture.py](../../tests/integration/window3_saved_t49_t50_capture.py) 通过确切 `--classification-task-id`、`--ms-task-id`、`--dynamic-task-id` 与 `--dataset-version-id` 读取共享 `sjia_simulation:5433` 中的三个 Task、TaskAttempt、Assessment/AssessmentOutput/AssessmentInput、AlertEvaluation、规则配置审批与验证、动态输入、信号、决定、事件、冻结集合分组及标签。数据库事务设为只读，拒绝其它数据库，要求 Task 已完成且各自只有一条保存结果。捕获患者事实版本、原值、比较符、单位、医学时间、来源版本、`available_at` 和核对时间，并逐项记录 payload 与保存结果的 assessment_at、mode、known_at。程序将每项保存结果 `inputs[]` 的 `record_version_id/field_id/verification_id` 与 Task `snapshot.selected_refs` 中捕获的准确事实引用关联；未匹配引用单独列出并阻止进入临床计算前置条件。逐事实输出 `available_at`、`verified_at`、核对字段结果、核对撤销时间、`available_by_known_at` 与 `verified_by_known_at`；后者要求时点内事实可用、核对结果为一致且核对未在该时点前撤销。汇总回放时点之后才可用或才核对的事实数量。Provider 与模型标为 `NOT_APPLICABLE`；确定性规则配置及执行制品摘要按数据库原值记录。输出写入忽略目录 `.planning-work/parallel/window3/T59-saved-rule-result-capture.json`。评价器通过 `--saved-rule-capture` 核对三个 Task、患儿、冻结集合版本、分组、mode、时间、准确配置 ID／版本／校验值、事实来源与结果输入关联。
