# sJIA 守护者联盟 UI 2.0 设计规范

日期：2026-10-07。能力：DESIGN。输入模式：PRD 2.0 与已有设计、现有路由的混合模式。当前交付是独立可点击设计，业务应用代码和服务保持原有状态。

## 设计方向

继承深蓝顶部、系统中文字体、三维功能图标、通用儿童形象及品牌 Logo。阅读区域采用浅蓝灰背景、白色卡片及温暖纸面，主要操作使用深蓝色。家庭内容准确、简短，专业配置和设计说明位于独立区域。

首页正文依次展示当前提示、孩子的记录、拍照主操作及体温与治疗入口。长期档案在记录中统一管理，首页提供直接相关的快捷入口。底部导航仅用于首页、记录、我的；二级页面使用返回入口。受控支持页面通过评审目录查看，不加入家庭导航。

当前版本名称表示 PRD 2.0 对应的 UI 交付。沿用已有品牌文件和设计方向，页面清单与资产清单采用本目录的当前定义。

## 布局与 Token

设计基准为 390 × 844 CSS px，适配 320、360、390、430、580 CSS px；主要内容自然滚动，底部导航与内容分别布局。桌面评审区域显示页面目录、手机画框与状态控制；手机独立入口保留 H5 页面及设计标识。画框高度适应浏览器可用高度，字体不整体缩小。

| 项目 | 规格 |
| --- | --- |
| 品牌顶部 | #173F70 至 #225990；白色标题；辅助信息 #C9DCF1 |
| 内容背景 | #F1F5FA；卡片白色；摘要使用温暖纸面 |
| 主要文字 | #243B55；正文与输入基准 16 px；页面标题 23 px |
| 卡片 | 圆角 20 px，白色上缘，轻微环境阴影；内容内边距 18—20 px |
| 间距 | 4 px 基础尺度；常用 8、12、16、20、24、32 px |
| 操作 | 主要按钮至少 52 px 高；主要触控目标至少 44 × 44 px |
| 导航 | 主页面固定三项导航；内容底部留出独立阅读区域 |
| 动效 | 180—240 ms；减少动态设置关闭非必要动效 |
| 焦点 | 3 px 蓝色外框与 3 px 间隔；弹层支持 Escape 和焦点返回 |

可维护数值见 tokens.json，运行样式由 src/tokens.css 与 src/styles.css 使用。主体控件采用普通中文，需求编号、路由、状态切换及服务说明放在评审区域。

## 组件与状态

| 组件 | 默认／操作 | 等待／失败／失效 |
| --- | --- | --- |
| Button | 深蓝主要操作，白色次要操作；焦点和按下均有反馈 | 禁用不可提交；设计预览操作反馈说明未执行真实保存 |
| Field | 标签独立、原值与单位分别填写；医学时间无当前默认值 | 未知可以明确保留；原文不能被共同时间覆盖 |
| Segments | 当前选项使用白色底与文字；支持触控与键盘 | 筛选不生成不存在的数据 |
| Patient | 展示选择患儿入口及资料归属 | 没有真实关系时不填入姓名或患者标识 |
| Record | 原值、时间、出处、核对状态及版本共同表达 | 来源或时间不足不能生成临床等级 |
| Batch | 逐页接收、处理、确认、归档；失败页与完成页分别统计 | 重试针对失败页，取消针对未开始页；当前没有真实批次数量 |
| Clinical status | 配合图标、标题及文字；关注琥珀、重要橙色、紧急红色 | 临床文字和启用条件仍需批准，设计色彩不定义临床阈值 |
| Sheet／Dialog | 返回、关闭和主要操作明确；关闭后恢复焦点 | 不用点击关闭表示提交或保存成功 |
| Summary | 保留范围、来源及时间，临床字段遵循可见权限 | 基准未知不输出变化，来源更正需重新生成 |
| Reminder | 默认关闭，独立于临床事件；可暂停与关闭 | 未完成提醒不改变健康状态；当前设置不发送通知 |

状态控件分为加载、空内容、读取失败、网络中断、权限失效、资料不足、版本失效、提交待确认、完成反馈和三级提示样式。完成及临床等级是明确标注的组件状态画稿，未绑定虚构病例；不作为真实记录、评估或送达证据。

## 资产与内容

复用现有儿童 Master 与 1x／2x PNG、Logo 及三个透明三维图标表，尺寸和来源见 asset-manifest.csv。角色保持原始比例，object-fit 使用 contain；不使用表情、肤色或动画表示病情。Logo 放于登录与我的页面，产品顶部保持任务标题。辅助方向、筛选和标准控件沿用已安装的 lucide-react 图标库。

无获准原件时不生成报告缩略图、病历、姓名、采样时间、检查数值或提示数量。文件选择只读取本人选择的真实文件元数据，在当前页面内显示，未上传、未识别、未写入浏览器持久存储。浏览器刷新后不承诺保留输入。正式应用的服务端草稿要求继续由 PRD 2.0 定义。

## 页面与交互交接

39 个产品页面的路由、PRD 关联和交互意图见 screen-design-map.csv 与 screens/page-specifications.md。受控支持页面的具体入口属于根据 PRD 推导的设计，不授予岗位权限。状态适用范围见 states/state-specifications.md 和 src/catalog.js 的 statesFor。

前端实施须连接真实当前权限、原件版本、批次任务、本人采用、专业核对、current／replay、批准内容与 Provider 回执。设计预览没有创建这些业务结果。页面只读占位文字表示数据未提供，不能作为成功结果传给正式服务。

## 检查范围

执行构建、清单与资产元数据检查，以及浏览器 DOM、布局边界、页面跳转、状态选择和键盘行为检查。按照用户限制不执行截图、图像识别或视觉比对，不声明像素一致性。真实手机、辅助阅读器和完整临床业务验收由后续实施完成。
