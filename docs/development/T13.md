关键采用结论：

- OCR 输出只进入候选区，候选含 raw_text、recognition_status、anchor、confidence；confidence 不产生核对资格。
- 每个候选必须 accepted/modified/unknown/excluded 决定；本人确认不授予专业核对资格。
- 确认后创建正式报告（report）、记录（record kind=report、origin_type=report_transcription、capture_method=ocr_confirmed）与 record_attachment。

## 当前功能与实现

UI2-03 使用原稿报告容器、文件介绍、列表、步骤和两项资料入口，连接现有文件接收与报告登记。每页显示真实识别状态和重试入口，原件通过权限读取；替换或移除关联后对应候选失效。核对区域保留报告资料、原值、比较符、单位、方法、参考区间及每项独立时间，草稿恢复时重新确认。未知采样时间保持 NULL，报告时间单独保存。

ReportCandidates 和客户端 AJV 要求 name、字符串 value、comparator、unit、reference、method、source_text。后台候选集合保存 report-recognition-2 结构版本，识别任务输入和 Outbox 事件继续使用 recognition-1 输入结构。source_text 采用实际识别返回的完整原文，SourceAnchor 与后台候选保留同一原文；原始 Provider 响应另行保存。原值通过 Pydantic 与 AJV 的相同 Decimal 规范分类，原文的小数位保留。带原件字段缺少 source_text 时，记录服务准确拒绝。

后台识别通过 Outbox／Celery 保存输入摘要、实际模型与请求、原始响应、计量和页来源。候选就绪状态为 awaiting_confirmation；服务要求四种本人决定，正式采用和报告保存在同一事务。当前 Worker 和 Beat 未运行，真实报告、用途配置、逐项正式采用、正向保存、任务恢复、权限变化和完整 UI2 业务保持待验收。

## 决策与约束

- `finalize_candidate_set` 要求全部候选已决定；`confirmed_report_fields` 过滤 excluded/unknown。
- 报告登记复用 T10 记录模型：record kind=report、origin_type=report_transcription，字段 confirmation_id 保留本人决定。
- 换组后旧候选失效；后台识别使用 T06 任务与租约机制。H5 同步 Ark 接口读取 backend/.env 配置；真实取消、权限变化及未知外部受理的查询恢复需要独立验收。
