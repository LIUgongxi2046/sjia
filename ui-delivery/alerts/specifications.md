# 预警状态、警告色与转换规格

版本 UI 3.0。本文件定义高保真交互设计。设计性质说明位于画稿外的评审区域与文档中。状态转换不读取病例、不调用评估接口、不执行风险计算。临床等级名称、触发条件和最终联系文字仍需临床与项目确认。

## 状态画面

| 状态 | 标题 | 颜色语义 | 主要入口 |
| --- | --- | --- | --- |
| pending | 等待评估 | 蓝灰，表示排队 | 查看已提交资料 |
| evaluating | 正在评估 | 蓝色，表示处理 | 查看评估进度 |
| incomplete | 需要补充资料 | 琥珀，表示缺项 | 补充采样时间 |
| clear | 当前没有有效预警 | 青绿，表示当前事件状态 | 查看评估记录 |
| attention | 铁蛋白历次结果持续上升 | 琥珀，表示变化关注 | 查看全部依据、就医联系 |
| warning | 发热伴皮疹、关节不适 | 橙色，表示重要提示 | 查看全部依据、就医联系 |
| urgent | 呼吸困难或难以唤醒需急诊 | 红色，表示紧急行动情景 | 查看紧急提示、就医联系 |
| expired | 本次提示已失效 | 蓝灰，表示有效性变化 | 查看更新记录 |
| failed | 暂时无法更新预警 | 蓝灰，表示读取异常 | 重新加载 |
| disabled | 预警服务未启用 | 蓝灰，表示服务状态 | 查看服务说明 |

青绿色结果不表示当前安全或疾病排除。资料不足与关注提示虽共享琥珀色，标题、图标、原因和操作分别表达其含义。读取失败不自动使用红色临床警告。

## 过程状态机

提交资料进入 pending；START 进入 evaluating。处理结果分别通过 PUBLISH_CLEAR、PUBLISH_ATTENTION、PUBLISH_WARNING、PUBLISH_URGENT、NEEDS_DATA、FAIL 进入对应状态。这些事件来自评审控制区；正式应用须使用后端的获准结果。

资料不足补充后通过 SUBMIT 回到 pending。失败通过 RETRY 进入 evaluating。服务启用通过 ENABLE 进入 pending。没有计时器自动返回成功结果，也没有前端阈值计算。

## 阅读与有效性

READ 只将 read 设置为 true，attention、warning、urgent 等级保持不变。重复查看不产生新的预警事件。界面不提供“点击即解除风险”的操作。

INVALIDATE 表示依据更正、核对撤销或内容失效，使当前结果进入 expired。重新提交后重新评估，不能直接恢复历史等级。expired 不允许 READ 将其改为当前有效结果。

## 内容与操作

首页优先显示当前提示，详情展示完整内容、发布时间、查看状态、依据记录和联系路径。历史提示标记失效原因。家庭仅更新本人阅读状态，不自行关闭、升级或降低临床结果。

首页卡片保留原因标题、一条就医行动、最近体温与时间、查看详情入口。完整说明、资料来源、核对状态、联系渠道及版本由详情承接。关注情景要求联系医生核对变化并确定就诊安排；重要情景要求就发热、皮疹和关节不适及时联系医生；紧急情景明确指定表现及立即急诊行动，使用条件句。行动文案的审批状态记录在外部评审区及交付文档中。

资料不足、未启用、处理失败等状态直接说明尚无就医判断或无法判断紧迫性；无有效预警只能表达没有新增就医安排，不能显示“无需就医”。联系面板展示联系人、电话、来源及核验时间；缺少获准信息时准确显示未配置，保留查看摘要入口。

详情显示引用记录版本、文案设计版本 UI-COPY-03，以及尚未发布的临床规则版本和确认状态。记录版本与规则版本不能互相代替。

预览提供 10 个可选情景及对应转换按钮。文件 preview/alert-machine.js 是纯状态转换代码，alerts/state-machine.mmd 是 Mermaid 转换图。检查分别覆盖有效转换、非法转换、阅读保持等级及失效后的状态限制。
