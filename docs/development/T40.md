## 原件上传与分页

`archive-upload-options` 根据当前批准 runtime、资料来源、用途、患儿和有效人员返回格式、容量、页数及准确授权。PNG、JPEG、WebP、PDF 和 UTF-8 文本完整保存。原件使用不可覆盖对象、实际 SHA256、字节数量、对象版本和独立文件身份；重复上传使用原身份核验全部字节。同一身份跨组使用、未启用格式、无效编码、加密或损坏 PDF、无法完整分页的文本立即拒绝。

PyMuPDF 1.27.2.3 已登记于依赖和锁定文件。PDF 解析及文本分页使用成熟库，保存每份文件的全部 FilePage、尺寸及准确内部页序。文本分页核验全部字符及页面边界，医学数值和日期原文保持。上传顺序通过 UploadPart 明确保存；乱序接收后重排全部页序，已完成上传组禁止增加原件。

上传组采用明确 client_group_id，资料来源不根据集合顺序自动选择。界面通过实际接口保存、重新读取并完成原件组；刷新仅保留不含资料正文的组标识。已经保存且尚未完成的原件组可以继续接收；无效文件的明确拒绝提示保持，更正后使用原上传组提交。隐藏页面清除本地文件队列和私人内容。完整原件读取核验 SHA256，使用受控请求及内存 Blob，关闭或进入后台释放内容。

## 用途副本与模型输入

处理方案绑定准确原件、对象版本、校验和、用途、环境、目标及授权。PDF 和文本必须明确选择 file_page_id；保存 source_page_number、媒体类型、解析版本及实际处理证明。处理 Artifact 校验范围包含分页、Pillow 处理、对象保存代码和锁定依赖。

指定 purpose_copy.requested 任务实际生成单页 PNG 副本，保存 Task、TaskAttempt、Outbox、准确输入及不可覆盖对象。复制处理移除元数据，执行批准区域处理，核验原页尺寸和内容摘要。独立模拟复核使用另一名获准人员，保存当前岗位、病例授权、auth_epoch、范围与实际复核输入；本人输入与临床批准分别注明 SIMULATION。

外发和内容读取重新核查当前原件、用途、准确副本、处理配置、来源、保留策略、独立复核及依赖。模型输入选择准确 file_page_id 对应副本，禁止多个原页混合选择。PDF 第一页已经实际调用 Ark，完整模型请求、候选、计量、耗时及准确第一页数值持续保存。撤销副本或准确外部用途授权后，对应内容禁止继续使用；家庭原件按独立权限读取。

## 处置申请与逐项结果

家庭入口读取本人获准对象和已批准处置策略，明确选择准确对象版本、范围及申请依据。创建使用持久 WriteIntent、正文、授权范围、幂等回执及原请求恢复；刷新读取同一申请和准确处理范围。病例、原件与目标用途范围均由当前授权核查。

支持页面接入当前申请、批准证明、逐项执行、继续保存及原任务重试。批准保存当前人员、岗位、病例范围、策略摘要、目标和文件版本。执行保存明确 Task 和 Outbox；每次处理重新核查准确输入、当前权限和批准证明。等待结果、失败、awaiting_resolution 与完成分别显示，查询在需要本人处理的状态结束。

本地删除核验准备证明、inode、device、修改时间、实际字节数及 SHA256。删除之后同步目录，保存不可覆盖的实际确认回执；同一操作重新读取原回执。逐项继续保存需要实际对象、证明及未来重新核查时间。家庭页面读取准确逐项状态，不使用申请完成标签代替删除证明。

独立模拟环境实际删除一份明确批准的用途副本，另一份登记继续保存；完整原件字节保持。没有启动全局 Worker 或 Beat。每项执行限定准确 purpose_copy.requested、archive_page.requested 或 disposition.local_requested 事件，不消费其他环境或其他资料。
