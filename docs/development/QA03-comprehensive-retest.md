# QA03 页面比对与模型功能复验

日期：2026-10-04。状态：本地验收完成。文档有效性：CURRENT。外部验收条件单独记录。

## 依据与环境

用户要求重新测试全部功能，逐页比对设计，使用测试数据检查模型功能和异常，修复发现的问题。依据 PRD、UI3 页面规范、后端 LLD、预警编排 LLD、QA01/QA02 开发记录及当前实现制定预期。

用户明确授权独立本地合成账号、病例、无患者信息图片、实际 Ark 调用及写入。使用 `sjia_qa03`、Django8001、Vite5174、Redis database3、独立 Celery Worker/Beat 和 `.qa-work/QA03/object-store`。全量 Django 回归使用 `test_sjia_dev`。项目没有 Git；证据与源码使用 SHA-256。

## 当前实现

共用标题、三维图标、卡片和表单；首页批准提示与实际观察；报告和治疗已有资料；原图 ImageViewer；四类档案及历史时间；摘要分类和依据版本；对象操作权限及更正初始状态已经更新。23 个设计页面完成结构比对，17 页位置断言、三种宽度和放大文字检查通过。

语音通过实际 Ark 提取候选，`VoiceCandidateReview` 提供逐项选择和修改、原文、体温单位及医学时间确认。确认前不改变表单；草稿保留采用来源；取消及患儿切换终止浏览器接收。

`recognition/jobs.py` 使用固定输入摘要、实际 Ark、Outbox 和 Celery 处理图片。候选保存真实模型、请求标识、原始响应、计量及页来源；就绪状态为 awaiting_confirmation。`recognition/confirmation.py` 与正式记录写入在同一事务完成四种本人决定，修改和未知状态分别保存，任务在确认写入后完成。相同输入保持幂等，显式重试创建关联新任务。

识别期间取消、原图失效、授权撤销及期限检查阻止采用失效结果。空白图片无项目时明确失败。上传限制文件组状态、有效页码、图片格式和尺寸。候选 Schema 使用 Pydantic 严格类型与额外字段限制。

趋势比较使用同项目、单位、方法、精度和时区；同时间冲突的两侧均停止比较。限定值和未知条件中断 Chart.js 曲线，点击数据点显示来源。
