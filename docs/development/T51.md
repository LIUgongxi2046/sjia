## 当前功能与实现

开发范围覆盖发布配置的当前资格、环境版本、组件关系、事务一致性和 UI2-36 管理入口。家庭首页、提示详情、提示历史、联系信息和摘要读取检查当前发布；受控接口负责准确输入与授权。通知服务消费该资格的完整发送流程由 T52 维护，正向发送仍待验收。

UI2-36 使用实际设计样式、Token、容器和弹层，完整保留六项条件、家庭展示文字、启用环境与条件齐备后启用操作。未授权时显示原设计的未知状态，禁止读取私密目录或提交。当前岗位分别提供配置、发布、联系和来源目录，以及十四项管理操作；目录分页绑定环境、账号、授权、当前资源摘要和实际运行容量。联系岗位仅能取得本人维护的准确联系批准正文。来源目录返回身份、状态和摘要，原始证明内容仍通过服务端批准来源读取。

选择版本后读取准确配置、批准、联系或发布内容。操作表单使用服务器返回的状态、版本、正文摘要、制品摘要和环境版本；批准、实际验证、启用及停用各自执行。家庭文字更改保存为新配置版本，新发布明确引用该版本。选择准确状态并重新核验后才提交；页面不自动批准内容，不自动调整接收许可。

提交使用实际规范路径、原请求 ID、intent、generation 和完整正文。刷新与后台恢复重新查询原意图；prepare 结果未知时可按原请求身份查询。已提交后重新读取对应资源，并核对保存版本和批准身份。结果未知时禁止新提交。明确 pending 且尚无 WriteRequest 的原意图可以按当前 generation 取消，取消与审计同事务保存，原正文保留；unknown、已经提交或 generation 变化时拒绝取消。取消记录不可重试，使用者能够更正输入并开始新的明确操作。页面隐藏、退出或权限变化时清除私密状态并取消读取，不在浏览器持久保存正文。

家庭配置采用严格的 content-1、visibility-1、notification-1、validation-1 和 summary-1 格式。准确环境、用途、获准来源、规则、窗口、独立报告、资料来源版本和当前制品需要一致；内容等级与规则的 publication.level 一致。独立验证报告必须来自实际批准来源并通过原规则验证检查。提示详情重新检查评估对应规则和窗口，来源字段为当前授权与可见配置的交集。历史显示当前内容资格。摘要保存 release_id 和 publication_epoch，读取及目录检查当前发布、准确可见配置、模板用途和字段范围；资格变化后返回需要重新生成，原始项目保留。联系读取使用当前运行环境。

发布读取返回准确组件、联系和验证配置 ID。保存时保留请求指定内容，按环境分配递增版本；批准只确认组件完整，不产生临床批准。启用检查七类配置、内容摘要、准确环境和批准范围、未撤销验证、联系来源、有效期限及期望环境版本。启用将发布 publication_epoch 与环境同步更新；停用核查当前发布身份并提升环境版本。

全部发布写入要求本人提交意图、请求 ID、generation 与正文摘要一致。重复提交读取原凭据；业务变更、凭据和审计同事务保存。发布读取与写入均要求 publish_config 服务权限及当前运行环境。

发布、联系及配置共十四项写入通过 requests.controlled 保存原始正文、准确目标、请求摘要和岗位授权信息。prepare、query、retry、submit 均核查当前账号、运行环境及对应岗位权限。查询返回正式 RequestView、原始 controlled_input 与已提交 WriteReceipt。重试要求 generation 一致、存在可恢复正文、目标仍满足期望状态，且没有对应 WriteRequest；结果无法确认时返回 unknown，禁止再次执行。提交同时核查当前保存策略，正文摘要使用 IntentInput 的 1.0.0 协议版本。

support 的本人请求目录仅包含当前有权访问的发布、联系及配置操作；分页容量由正式运行配置确定，签名游标关联账号、权限、请求摘要和查询容量。请求变化后游标失效。家庭申请目录保持原有行为。已提交凭据的资源版本取持久 WriteRequest，并要求 AuditEvent 的主体、操作、对象、保存版本、请求标识、完成时间及保存策略全部一致；后续资源状态变化不改变历史凭据。

联系保存、启用与停用采用独立接口及 manage_contacts 权限。保存完整保留 ContactInput，维护主体和运行环境由当前授权确定；准确内容对应 `content/contact-1` 配置正文。新增版本为 draft，verified_at 为空。启用校验来源、有效期、准确批准内容、配置批准与环境验证；停用核查状态及版本。启用和停用同步提高环境版本及 publication_epoch。既有 create_contact_version 与 activate_contact 入口调用相同领域服务。

配置八项接口采用独立 manage_configs、approve_config、register_validation、publish_config 权限。配置正文按具体 Schema 校验；保存为 draft，提交进入 pending，批准、登记实际验证及启用分别操作。真实批准和验证报告从批准来源读取并核验文件摘要、用途、环境、执行人和当前制品；验证 outcome 从报告取得。启用核查期望环境版本，停用及撤销批准使已登记依赖失效。完整证明格式见 [configuration-evidence.md](../../backend-design/configuration-evidence.md)。purpose-processing-2 保留准确原件和病例范围检查，恢复及重复提交也重新检查当前访问资格。

`provider/archive-quota-1` 已登记为正式配置类型，使用 `archives.quota` 的严格 Schema 与跨字段校验。配置必须提供准确 runtime、Provider、模型、测量证据、计价证据、逐页预留、批次与每日预算、并发数量、时区及执行期限；系统不填写默认额度或价格。保存、批准、验证与启用继续使用现有岗位和证明机制，没有创建运营角色或批准记录。消费时的当前引用、费用资格及实际预算处理由 T42 完成。

字段配置、发布组件、联系配置和摘要的模板／可见策略通过 configurations.qualification 执行相同的当前资格读取。家庭采用要求准确环境、Schema、正文摘要、family audience、当前批准来源、实际验证报告、制品摘要及执行人员证明。读取路径不写入业务资料；写入路径在同一证据判定基础上锁定相关记录。

字段入口严格接收 kind 与可选 version，当前关系和 read_raw 字段范围决定可见定义；writable 为配置许可与当前 write_record 字段范围的交集。指定历史版本且当前证明仍有效时返回 read_only，全部字段不可写；证明无效时不返回字段。摘要详情及目录采用一致事务读取；正文资格失效时 needs_regeneration 为 true，items 为空，数据库原始项目继续保留。
