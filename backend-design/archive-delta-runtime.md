# 新增内容整理的运行与可见字段

当前设计为 ACCEPTED，范围为 FR-18、GRAC-06 的确定性档案整理。来源为 PRD 第8.19.6节、HLD 的长期档案与摘要边界，以及用户2026-10-18委托全部软件开发与批准的授权。维护责任为当前后端实现；T46、QA19维护业务验证状态。

## 配置与访问

backend-runtime-1 增加可选 UUID 字段 archive_delta_visibility_config_id。建立新增内容整理请求时必须明确提供该字段，并指向当前环境、purpose为family_observation的visibility-1配置，clinical_fields必须为空。准确配置需要有效来源、批准、当前代码验证及启用状态。缺少引用、错误类别、错误环境、错误用途或不允许的临床字段立即返回503与ARCHIVE_DELTA_VISIBILITY_UNAVAILABLE。

该引用用于本人档案整理的字段范围。家庭提示和就医摘要继续使用各自发布、联系、内容及可见性检查。档案整理继续逐项检查本人身份、患儿、原件用途、字段权限、记录、文书版本、专业状态及全部来源，不由运行配置增加病例权限。

| 字段 | 持久化与读取 | 使用及验证 |
| --- | --- | --- |
| archive_delta_visibility_config_id | ConfigVersion.payload；UUID；仅运行配置使用 | batch_runtime取得准确运行版本，material_scope选择准确visibility配置 |
| visibility_policy_id | 原有请求冻结内容、Task.input_refs和DeltaSummary | 当前生成引用配置，历史结果使用原冻结身份重新核验 |
| field_codes | visibility-1原有字段 | 每项真实事实仍需当前read_raw及原件权限 |
| clinical_fields | visibility-1原有字段；档案整理必须为空 | 不提供分类、评分或临床等级 |

## 版本与运行

已有运行配置无需为其他功能增加该字段；新增内容整理在完成明确配置之前保持不可用。配置人员选择准确可见性版本，登记新的运行配置，验证并启用；进程采用当前运行版本。没有自动选择其他策略或继承家庭发布配置的路径。

生成任务仍使用summary任务政策，明确执行、租约、并发和单次尝试预算，全部生成结果及来源在同一事务保存。当前确定性整理不调用外部模型。既有请求和结果继续使用冻结的visibility_policy_id读取历史依据；新配置、来源、更正、权限或核对变化由现有context比较及依赖节点判定失效，失效结果不返回当前项目正文。原请求身份和幂等回执继续保留。

同次material_scope调用内，相同准确文书版本的来源及完整字段权限核验保存在局部变量。原件处置、环境、主体及患儿仍使用既有读取范围与事务保护；每项事实继续核验实际字段、记录、核对和来源引用。不同文书版本分别读取和核验，局部结果不跨事务或请求使用。

局部来源复用要求涉及的全部病例授权与患儿关联均没有结束时间。存在明确结束时间时，每项事实重新检查文书范围，持续采用实际时间判定权限，不延长原授权期限。

批次页数使用runtime.limits.max_pages核验，文书数量继续保持100份上限，请求冻结内容继续受api.max_json_bytes限制。api.max_page_size控制分页结果范围。各项限制独立执行，超限返回422与ARCHIVE_DELTA_SCOPE_LIMIT_EXCEEDED。

## 验收

使用已获准119页真实批次、准确文书与83项未专业核对事实。配置缺少和范围超限分别核验；新配置采用后执行真实意图、生成、持久任务、回执、重复提交、读取、准确来源及页面验证。没有比较基准时仅列新增与待处理事项，字段状态、原值及未知时间保持。撤权后拒绝正文，更正或策略变化后停用失效内容。真实独立临床评价及设备验收继续由原任务负责。
