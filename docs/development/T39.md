## 实施与来源

全部新增实体具有 UUID；同患儿复合外键、不可变版本、当前指针、范围、状态、JSON 类型、精度与索引由固定 SQL migration 创建，Django state 与 ORM 分别核验。未来结构调整新增 migration，已发布 DATA SQL 的摘要必须保持。SQL migration 不提供删除历史实体的反向操作。

历史字段按准确 field_id 创建一个事实身份与一个初始版本，不根据名称或数值合并两个字段，也不猜测旧更正的逐字段对应。旧 RecordVersion 自身的历史引用保持；正式更正后由领域动作维护明确 FactVersion 关系。context_type、assertion_state 和 availability_status 缺少证据时保存 unknown，available_at 保持 null；medical_time 和原文保持原值，time_origin=legacy。新 archive 只组织原有患儿资料，不增加病例。
